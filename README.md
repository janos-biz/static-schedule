# ESG 일정/담당자 보드

날짜별 계획 파일 `plan-YYMMDD.md` 를 데이터 저장소로 쓰는 사내망용 일정 확인 화면입니다. 별도 백엔드/DB 없이
서버가 계획 파일을 직접 읽고 씁니다.

## 주소 세 개 — 보기, 편집, 유지보수

| 주소 | 용도 | 비밀번호 |
| --- | --- | --- |
| `/` (기본) | **읽기 전용.** 담당자·상태·진행률을 값으로만 보여 줍니다. 체크박스·완료 버튼·릴리즈 버튼·일괄 변경이 없어 실수로 고칠 수 없습니다. 공유용 주소입니다 | 없음 |
| `/admin` | **편집.** 배정·상태 변경·완료·릴리즈 기록을 할 수 있습니다 | 필요 |
| `/maintain` | **작업 유지보수.** `/admin` 기능에 더해 작업 행(ID·작업키·IA키·분류·일정·백엔드·담당자·화면번호) 추가·수정·삭제, `담당자 관리`·`계획 일정 관리`·`표시 이름 관리`, 로그아웃 옆 `버전 업데이트`를 쓸 수 있습니다 | `/admin`과 다른 비밀번호 필요 |

- 세 주소 모두 같은 계획 파일을 봅니다. `?date=260813` 도 똑같이 씁니다 (예: `/maintain?date=260813`).
- 다른 사람이 `/admin` 또는 `/maintain` 에서 저장한 내용은 읽기 전용 화면에도 몇 초 안에 반영됩니다.

### 편집 비밀번호 (.env)

계획 파일 폴더(docker 에서는 `docker-compose.yml` 이 있는 폴더)에 `.env` 를 두고 비밀번호를 적습니다.
`.env.example` 을 복사해서 값만 바꾸면 됩니다.

```bash
cp .env.example .env
# .env 안에서 ADMIN_PASSWORD와 MAINTAIN_PASSWORD를 서로 다른 값으로 바꿉니다
```

- `.env` 는 **git 에 올라가지 않습니다**(`.gitignore`). 서버 폴더에만 둡니다.
- 저장하면 **서버를 다시 띄우지 않아도 바로 적용**됩니다. 대신 그때 로그인해 있던 사람은 모두 다시 로그인해야 합니다.
- `docker-compose.yml` 의 `environment:` 에 두 비밀번호를 직접 넣어도 됩니다. 그 값이 `.env` 보다 우선합니다.
- `ADMIN_PASSWORD`가 없으면 `/admin`, `MAINTAIN_PASSWORD`가 없으면 `/maintain`이 각각 잠깁니다.
- 로그인하면 서버가 12시간짜리 쿠키(HttpOnly)를 내려 줍니다. 브라우저에 비밀번호가 저장되지는 않습니다.
  헤더의 `로그아웃` 으로 바로 풀 수 있고, 5회 연속 틀리면 1분간 잠깁니다.
- 두 역할의 쿠키는 분리됩니다. `/admin` 로그인으로 `/maintain` 잠금이 열리지 않으며 반대도 같습니다.
- 막는 지점은 **저장(`PUT /plan-file`)** 입니다. 두 역할 중 하나로 로그인해야 저장할 수 있고 읽기(`GET`)는 누구나 가능합니다.

## 실행 (docker · 상시 운영용)

`docker-compose.yml` 이 있는 폴더가 그대로 데이터 폴더입니다. 그 폴더의 `plan-*.md` 를 읽고 씁니다.

```bash
docker compose up -d --build
```

- 접속(보기): http://localhost:5180 · 같은 사내망의 다른 PC/모바일에서는 `http://<서버 IP>:5180`
- 접속(편집): http://localhost:5180/admin
- 접속(작업 유지보수): http://localhost:5180/maintain
- 로그: `docker compose logs -f` · 종료: `docker compose down` · 재시작: `docker compose restart`
- `restart: unless-stopped` 라 **서버를 재부팅해도 다시 뜹니다.** 터미널을 닫아도 계속 돕니다.
- 계획 파일을 고치거나 새로 복사해 넣으면 컨테이너를 다시 띄울 필요 없이 바로 반영됩니다
  (파일 목록은 매 요청마다 폴더를 다시 읽습니다). **소스 코드**를 고쳤을 때만 `--build` 로 다시 빌드하세요.

계획 파일만 따로 두고 싶으면 `docker-compose.yml` 과 `plan-*.md` 를 같은 폴더에 놓고, 이미지는 미리 빌드해
둔 것을 쓰면 됩니다. (`build: .` 을 `image: static-schedule` 만 남기고 지우기)

| 설정 | 위치 | 기본값 |
| --- | --- | --- |
| 계획 파일 폴더 | `volumes: - ./:/data` | compose 파일이 있는 폴더 |
| 포트 | `ports: - "5180:5180"` | 5180 |
| 시간대 | `environment: TZ` | `Asia/Seoul` (완료 시각·릴리즈 이력이 이 시간으로 기록됩니다) |
| 편집 비밀번호 | 계획 파일 폴더의 `.env` (`ADMIN_PASSWORD`) | 없음 — 넣지 않으면 `/admin` 이 잠긴 채로 열리지 않습니다 |
| 유지보수 비밀번호 | 계획 파일 폴더의 `.env` (`MAINTAIN_PASSWORD`) | 없음 — 넣지 않으면 `/maintain` 이 잠긴 채로 열리지 않습니다 |

## 실행 (개발용)

```bash
npm install
npm run dev
```

- 내 PC: http://localhost:5180 (편집은 `/admin`, 작업 행 관리는 `/maintain`)
- 같은 와이파이의 다른 PC/모바일: 터미널에 찍히는 `Network:` 주소 (예: http://10.150.208.175:5180)
  - 접속이 안 되면 macOS 방화벽에서 node 수신 허용을 확인하세요.
- 계획 파일은 프로젝트 폴더에서 읽습니다. `PLAN_DIR=/다른/폴더 npm run dev` 로 바꿀 수 있습니다.
- 서버를 끄면 화면도 닫힙니다. 계속 띄워두고 쓰려면 위의 docker 방식을 쓰세요.

docker 없이 빌드본만 돌리려면:

```bash
npm run build
PLAN_DIR="$PWD" npm start      # http://localhost:5180
```

## 계획 날짜 선택

- 화면 **최상단**의 `계획 날짜`에서 날짜를 고르면 그 날짜의 `plan-YYMMDD.md` 를 읽어옵니다.
  담당자 배정·상태 변경 등 모든 수정도 **선택한 날짜의 파일에만** 저장됩니다.
- 처음 열면 가장 최근 날짜 파일이 열립니다. `← 이전` / `다음 →` 로 하루씩 넘길 수 있습니다.
- 고른 날짜는 주소에 `?date=260806` 형태로 남아, 새로고침하거나 링크를 공유해도 같은 파일이 열립니다.
- **새 버전 만들기**: `/maintain`에서 최신 파일을 보고 있을 때 로그아웃 옆 `버전 업데이트`를 누르면 그 파일을 내용 그대로
  복제한 `plan-<오늘 YYMMDD>.md`가 만들어지고 화면이 새 파일로 넘어갑니다. 이후 편집은 새 버전에 저장되고 원본은
  그대로 남습니다. 오늘 날짜 파일이 이미 있거나 최신이 아닌 파일을 보고 있으면 버튼이 잠깁니다(서버 `POST /plan-version`,
  `/maintain` 로그인 필요, 기존 파일은 덮어쓰지 않음). 폴더에서 직접 복사해도 됩니다.

  ```bash
  cp plan-260806.md plan-260810.md
  ```

## 화면

| 탭 | 내용 |
| --- | --- |
| 담당자 배정 (기본) | 화면 전체를 엑셀 시트처럼 놓고 퍼블담당·검수담당·상태·진행률을 셀에서 바로 편집. 진행 상황 표시와 완료 버튼 제공, 체크박스로 여러 건 일괄 배정. **행을 클릭하면 그 중분류에 속한 화면번호(UI-ESG-*)가 펼쳐집니다**. 읽기 전용(`/`)에서는 `작업 현황` 이라는 이름으로 같은 표를 값만 보여 줍니다 |
| 대시보드 | 전체 진행률, 담당자별 퍼블/검수 배정 현황, 대분류별 진행 |
| 주차 일정 | 대분류 × 주차 공수 히트맵(이번 주 강조), 퍼블담당별 주차 부하 추정 |
| 화면 목록 | 중메뉴별 화면번호(UI-ESG-*). 행(중메뉴)을 누르면 아코디언으로 펼쳐져 그 중메뉴의 화면번호·화면명이 나옵니다 |

담당자 배정 표는 **계획일정의 마감일(종료)이 빠른 순**으로 정렬됩니다. 마감일이 같으면 시작일이 빠른 쪽이,
그것도 같으면 계획 파일의 행 순서가 먼저 옵니다. 계획일정 컬럼이 없는 옛 파일은 파일에 적힌 순서 그대로 나옵니다.

## plan 단일 SoT: 파일이 곧 데이터베이스

웹 화면은 선택한 `plan-YYMMDD.md` 하나만 읽고 씁니다. 외부 screen-map JSON, 빌드 시점 생성 데이터, 별도 DB는 없습니다.
파일의 섹션은 **저장 데이터**와, 저장할 때마다 저장 데이터에서 다시 계산해 쓰는 **파생 데이터**로 나뉩니다.

| plan 섹션 | 종류 | 역할 · 편집 위치 |
| --- | --- | --- |
| `## 담당자` | 저장 | `이름 · 백엔드 · 퍼블 · 검수`(역할에 `O`). 작업의 백엔드·퍼블담당·검수담당 선택 목록. `/maintain` `담당자 관리` |
| `# 제목`(첫 줄) | 저장 | 페이지 제목. 화면 상단 제목과 브라우저 탭 제목에 함께 쓰입니다. `/maintain` `표시 이름 관리` |
| `## 표시 설정` | 저장 | 표 헤더(대분류·중분류·백엔드·퍼블담당·검수담당)와 상태(대기·퍼블·검수)의 화면 이름. `/maintain` `표시 이름 관리` |
| `## 주차 일정` | 저장 | `주차 · 시작 · 종료`. `/maintain` `계획 일정 관리` |
| `## IA` | 저장 | `IA키 · 상위 IA키 · 구분 · 명칭 · 순서`로 대분류/중분류/메뉴 계층 정의 (파일에서 직접 편집) |
| `## 작업 목록` | 저장 | 안정적인 `작업키`와 담당 IA 범위인 `IA키`를 일정·담당자·상태와 함께 정의. `공수` 칸만 파생 |
| `## 화면 목록` | 저장 | `화면ID · 화면명 · IA키 · 작업키`로 화면의 IA 위치와 담당 작업을 연결 |
| `## 릴리즈 이력` | 저장 | 릴리즈(개발 이관) 기록 |
| 작업 목록 `공수` | 파생 | 그 작업키에 연결된 `## 화면 목록` 행 수 |
| `프로젝트 기간` · `최종 수정` | 파생 | 첫 주차 시작 ~ 마지막 주차 종료(주차 수) · 저장한 날 |
| `## 대분류별 주차 공수` | 파생 | 시작일이 속한 주에 착수하는 화면 건수 |
| `## 종료 기준 누적 완료율` | 파생 | 종료일이 속한 주에 공수가 끝난다고 본 누적 비율 |

파생 데이터는 직접 고쳐도 다음 저장 때 다시 계산됩니다. `## 담당자` 표가 없는 옛 파일은 `- 프론트 담당자:` 줄(퍼블·검수)과
작업에 적힌 백엔드 값으로 명단을 만들고, 처음 담당자를 편집해 저장할 때 표가 `## 작업 목록` 앞에 만들어집니다.
작업에 일정이 없는 아주 오래된 파일은 주차 공수 표를 적힌 값 그대로 씁니다.

`/maintain`에서 작업을 추가하거나 수정할 때 `화면번호 (UI-ESG-*)`에 번호를 쉼표 또는 공백으로 구분해
입력하면 `## 화면 목록`에 선택한 IA키·작업키 매핑으로 함께 저장됩니다. 기존 화면번호는 편집창에 다시 표시되며,
번호를 빼면 해당 작업의 매핑도 제거됩니다. 새 매핑의 화면명은 우선 화면번호와 같게 저장되므로 필요한 경우
`## 화면 목록`에서 실제 화면명으로 바꿀 수 있습니다. 파일을 직접 편집해 행을 추가하는 방식도 계속 지원합니다.
저장 결과는 즉시 검색·펼침·화면 목록에 반영되며 Docker 재빌드는 필요하지 않습니다.
공수는 연결된 화면 수로 자동 계산되므로 화면번호를 붙이거나 떼면 공수와 주차 공수가 함께 바뀝니다.

### 담당자 배정 표에서 펼치기

배정 표의 행을 클릭하면 **릴리즈 기록 상자**(릴리즈 완료 버튼 · 마지막 릴리즈 시각 · 이력)와 그 **중분류**에
해당하는 화면번호가 아래에 펼쳐집니다. 필터 줄의
`화면번호 모두 펼치기` 로 한 번에 열 수도 있습니다. 담당자·상태·진행률 **셀을 조작할 때는 접히지 않습니다**
(select·체크박스·완료 버튼 위의 클릭은 펼침 토글로 치지 않습니다).

화면의 `작업키`가 작업 목록에 없거나, 화면·작업의 `IA키`가 IA 표에 없거나, 화면ID가 중복되면 웹 화면에
plan 연결 오류가 표시됩니다. IA나 화면 매핑을 조사할 때 Domain Atlas를 참고할 수 있지만, 조사 결과는 반드시
plan 표에 기록해야 하며 static-schedule 런타임은 Atlas에 연결하지 않습니다.

IA·화면 표가 없는 구버전 plan은 해당 파일의 작업 대·중분류와 비고에 있는 `UI-ESG-*`만으로 임시 목록을 구성합니다.
구버전 호환 역시 plan 파일 밖의 데이터를 읽지 않습니다. 구버전 작업의 화면번호를 `/maintain`에서 저장하면
합성된 IA와 편집한 화면 매핑을 `## IA`, `## 화면 목록`으로 문서에 추가해 이후부터 구조형 plan으로 보존합니다.

## 데이터 규칙 (plan-YYMMDD.md)

- **퍼블담당 / 검수담당** = 프론트 배정 대상. `## 담당자` 표에서 퍼블·검수 역할을 가진 사람만 고를 수 있고, 화면에서 바꾸면 바로 파일에 기록됩니다.
- **백엔드** = 화면별 백엔드 담당. `/maintain`의 작업 수정에서 `## 담당자` 표의 백엔드 역할 중에서 고릅니다.
- **계획일정(시작 / 종료)** = 작업의 시작계획일 / 종료계획일. `/maintain`의 작업 수정에서 바꿉니다.
  표에서는 **기본으로 접혀 있고**, 필터 줄의 `계획일정 보기` 버튼으로 펼칩니다(선택은 브라우저에 기억됩니다).
  접혀 있어도 화면명에 마우스를 올리면 날짜가 나오고, 정렬 기준(마감일 빠른 순)도 그대로입니다.
  이 두 컬럼이 없는 옛 파일도 그대로 열리며, 그 경우 `—` 로 표시됩니다.
- **상태**: 대기 → 퍼블 → 검수. 상태를 바꾸면 진행률이 그 단계 값(대기 0% / 퍼블 25% / 검수 75%)으로 맞춰집니다.
  작업 목록에는 이 세 코드가 저장되고, 화면·완료 버튼·진행 상황 문구는 `## 표시 설정`의 이름을 씁니다
  (예: `퍼블 → 계획`이면 완료 버튼이 `계획 완료`). 상태 칸에 표시 이름을 직접 적어도 코드로 읽습니다.
- **진행 상황** = 상태와 진행률을 함께 읽은 값이며, 표에 별도 컬럼으로 표시됩니다. 진행률은 0 / 25 / 50 / 75 / 100%
  다섯 단계를 씁니다.

  | 상태 | 진행률 | 진행 상황 |
  | --- | --- | --- |
  | 대기 | 0% | 착수 전 |
  | 퍼블 | 25% (50% 미만) | 퍼블 진행중 |
  | 퍼블 | 50% | 퍼블 완료 · 검수 대기 |
  | 검수 | 50% 미만 | 검수 대기 |
  | 검수 | 75% (50~99%) | 검수 진행중 |
  | 검수 | 100% | 검수 완료 |

- **완료 버튼**: 상태가 퍼블이면 진행률을 50%(퍼블 완료), 검수면 100%(검수 완료)로 올립니다. 퍼블 완료 후
  상태를 `검수`로 바꾸면 진행률이 75%(검수 진행중)가 됩니다.
- **퍼블완료 / 검수완료** = 그 단계 완료에 **도달한 시각**(`2026-08-07 14:32` 형식)입니다. 완료 버튼을 누를 때는
  물론 상태·진행률을 직접 바꿔 완료가 된 경우에도 같은 기준으로 기록되고, 완료에서 벗어났다가 다시 완료되면
  새 시각으로 덮어씁니다(마지막 완료 시점이 남습니다). 표에서는 `진행 상황` 칸 아래 작은 글씨로 보입니다.
  이 컬럼이 없는 옛 파일도 그대로 열리며, 그 파일을 처음 저장할 때 컬럼이 자동으로 추가됩니다.
- **릴리즈(개발 이관)**: 계속 다시 일어나는 일이라 덮어쓰지 않고 **이력으로 쌓습니다**. 배정 표에서 행을 클릭해
  펼치면 `릴리즈 완료` 버튼과 지금까지의 기록이 나오고, 누를 때마다 `## 릴리즈 이력` 표에 한 줄
  (`일시 · ID · 대분류 · 중분류 · 비고`)이 최신순으로 추가됩니다. 표의 `릴리즈` 컬럼에는 **마지막 릴리즈 날짜·시간**과
  누적 횟수가 표시되고, 잘못 누른 기록은 펼침 영역에서 `삭제`로 지울 수 있습니다.
  기록이 하나도 없으면 계획 파일에 이 섹션이 만들어지지 않습니다.
- **비고**: 화면 표에서는 빼고 표시하지 않습니다. 계획 파일의 `비고` 칸 값은 그대로 보존되며 파일에서 직접 고칠 수 있습니다.
  신규 형식의 화면 연결은 비고가 아니라 `## 화면 목록`에서 관리합니다.
- **화면번호 매핑**: `/maintain`의 작업 추가·수정 drawer에서 `UI-ESG-숫자M` 또는 `UI-ESG-숫자P` 형식으로
  입력합니다. 소문자는 대문자로 정규화하고 중복은 한 번만 저장하며, 형식 오류나 다른 작업에 이미 연결된 번호는 저장을 막습니다.
- 인원을 추가·변경하려면 `/maintain`의 `담당자 관리`를 쓰거나 `## 담당자` 표를 고칩니다. 이름을 바꾸면 배정된
  작업에도 함께 반영되고, 배정이 남은 사람을 빼거나 그 역할을 지우면 저장이 막힙니다.
- 작업을 추가하려면 `/maintain`의 `작업 추가`를 쓰거나 `## 작업 목록` 표에 행을 추가합니다. **ID는 다른 행과 겹치지 않게**
  지어 주세요. 공수·주차 공수·누적 완료율은 다음 저장 때 자동으로 다시 계산됩니다.
- `## 메모` 등 표 밖의 내용은 저장 시에도 그대로 보존됩니다.
